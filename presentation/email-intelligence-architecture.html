Division of work · Who does what

Code finds the facts, the model reasons over them, a person decides

Code

Deterministic steps

Directory lookup, rule keyword matching, deadline resolution, risk as the highest triggered rule, specialist routing.

Repeatable
Search

Retrieval

Categories, rules, policy sections and similar cases, each with an ID, an excerpt and a score.

Cited
Model

Reasoning and writing

Extraction, classification, confirmation of candidate rules, briefing and the draft. Output is validated against a schema.

Structured JSON
Person

Review and approval

The specialist edits the draft, approves it and triggers the simulated send. Nothing completes without this step.

Final decision
Order of operations inside the assessment

Rule keywords select candidate rules first. The model then confirms or rejects each candidate and cannot add a rule that was not retrieved. The overall risk equals the highest triggered rule, and the model may only raise it with a stated reason.

Governance · Guardrails

The agent reports potential risks and a person owns every outcome

Potential risk wording

Findings say "potential". Text that claims a violation occurred is rewritten.

Cited findings

Each finding lists rule and policy IDs. Invented IDs are dropped.

Human approval

A person approves the reply. The send is simulated and no real email leaves.

Email as untrusted data

The body sits in a delimited block. Instructions inside it are ignored.

Labelled output

AI and DEMO badges mark content. Provider and model appear in the log.

Failure handling

Rate limits trigger retry, then a logged fallback. Invalid JSON gets one repair.

The agent prepares and a specialist decides. The assessment is not legal advice and uses fictional demo rules.
